# SRS v1.0.042 - Gemini CLI 기능 사양서

**버전**: v1.0.042
**작성일**: 2026-02-13
**대상**: `gemini-ai-chat-code01.py` 및 관련 모듈

## 1. 소개

### 1.1 목적
본 문서는 Google Gemini API를 활용한 터미널 기반 AI 코딩 어시스턴트인 **Gemini CLI**의 기능적/비기능적 요구사항을 정의합니다. 사용자가 터미널 환경에서 효율적으로 코드를 작성, 수정, 실행할 수 있도록 지원하는 것을 목표로 합니다.

### 1.2 범위
- Gemini API (REST) 연동 및 대화 처리
- 프로젝트 파일 컨텍스트 분석 및 관리
- CLI 기반 사용자 인터페이스 (명령어, 입력 처리)
- 코드 실행 및 쉘 명령어 처리
- 파일 시스템 변경 감시 및 자동화

## 2. 기능 요구사항 (Functional Requirements)

### 2.1 대화 및 컨텍스트 (Chat & Context)

#### FR-1: 대화 인터페이스
- **FR-1.1**: 사용자와 Gemini 모델 간의 자연어 대화를 지원해야 한다.
- **FR-1.2**: 스트리밍(`stream`) 모드를 기본으로 지원하며, 필요 시 논스트리밍(`nostream`)으로 전환 가능해야 한다.
- **FR-1.3**: 멀티라인 입력을 지원해야 한다.
  - **입력**: Enter (새 줄), Ctrl+Enter (전송)
  - **명령어**: `/multiline` 커맨드로 명시적 모드 진입 가능

#### FR-2: 컨텍스트 관리
- **FR-2.1**: `/context <pattern> [question]` 명령어를 통해 특정 파일의 내용을 프롬프트 컨텍스트로 포함해야 한다.
  - 질문 생략 시 자동으로 멀티라인 입력 모드로 전환되어야 한다. (v1.0.041)
- **FR-2.2**: `/files` 명령어로 프로젝트 파일 목록을 확장자별로 필터링하여 조회할 수 있어야 한다.
- **FR-2.3**: `/tree` 명령어로 프로젝트 디렉토리 구조를 트리 형태로 시각화해야 한다.
- **FR-2.4**: `/read <pattern>` 명령어로 특정 파일의 내용을 읽어 출력해야 한다.

#### FR-3: 파일 및 코드 관리
- **FR-3.1**: AI 응답에 포함된 코드 블록(`filename:` 형식)을 파싱하여 `/save` 명령어로 파일에 저장해야 한다.
- **FR-3.2**: `/diff` 명령어를 통해 AI가 제안한 코드와 현재 파일의 차이점(Diff)을 보여줘야 한다.
- **FR-3.3**: `/apply` 명령어를 통해 Diff 내용을 실제 파일에 적용해야 한다.

### 2.2 작업 환경 및 도구 (Workspace & Tools)

#### FR-4: 작업 디렉토리
- **FR-4.1**: `/workspace [path]` 명령어로 작업 디렉토리를 변경할 수 있어야 한다.
- **FR-4.2**: 디렉토리 변경 시 `FileManager`, `ContextBuilder`, `FileWatcher`가 새 경로로 갱신되어야 한다.

#### FR-5: 코드 실행 및 쉘
- **FR-5.1**: `/run [lang]` 명령어로 마지막 AI 응답에 포함된 코드를 실행해야 한다. (지원: python, js, bash)
- **FR-5.2**: `/shell <cmd>` 명령어로 쉘 명령어를 실행할 수 있어야 한다.
- **FR-5.3**: `/shell! <cmd>` 명령어로 위험한 쉘 명령어(예: 삭제)를 사용자 확인 후 실행해야 한다.

#### FR-6: 템플릿 및 감시 (Advanced Features)
- **FR-6.1**: `/template <name>` 명령어로 시스템 프롬프트를 미리 정의된 템플릿(예: 리팩토링, 코드리뷰 등)으로 변경할 수 있어야 한다.
- **FR-6.2**: `/watch <pattern>` 명령어로 특정 파일 패턴의 변경을 실시간으로 감지해야 한다.

### 2.3 히스토리 관리 (History Management)

#### FR-7: 대화 기록
- **FR-7.1**: 메모리 상에 대화 내용을 유지하고 `/history` 명령어로 조회할 수 있어야 한다.
- **FR-7.2**: `/save_history [name]` 및 `/load_history [name]` 명령어로 대화 내용을 JSON 파일로 영구 저장 및 복원해야 한다.
- **FR-7.3**: `/clear` 명령어로 대화 내용을 초기화해야 한다.

## 3. 인터페이스 요구사항 (Interface Requirements)

### 3.1 CLI 입력 (CLI Input)
- **IR-1**: `readline` 라이브러리를 사용하여 **Tab 자동완성**을 지원해야 한다. (v1.0.031)
  - 지원 대상: 명령어(`/`), 파일 경로
- **IR-2**: 화살표 키(↑, ↓)를 사용하여 명령어 히스토리를 탐색할 수 있어야 한다.

### 3.2 출력 형식 (Output Format)
- **IR-3**: AI 응답은 실시간으로 스트리밍되어 출력되어야 한다.
- **IR-4**: 코드 블록은 Markdown 형식(` ``` `)으로 구분되어야 한다.
- **IR-5**: 오류 메시지는 `❌`, 성공 메시지는 `✅`, 정보 메시지는 `💡` 이모지를 사용하여 시각적으로 구분해야 한다.

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능 (Performance)
- **NFR-1**: 스트리밍 응답은 지연 없이 즉각적으로 표시되어야 한다.
- **NFR-2**: 대용량 파일 컨텍스트 추가 시에도 CLI 반응성을 유지해야 한다.

### 4.2 안정성 (Reliability)
- **NFR-3**: API 호출 실패 시 자동 재시도(Retry) 메커니즘이 동작해야 한다.
- **NFR-4**: 잘못된 명령어 입력 시 프로그램이 종료되지 않고 오류 메시지를 출력해야 한다.

### 4.3 보안 (Security)
- **NFR-5**: API Key는 환경 변수(`GEMINI_API_KEY`)를 통해서만 로드되어야 한다.
- **NFR-6**: `rm`, `del` 등의 파괴적인 쉘 명령어는 `/shell!` 명령어를 통해서만, 사용자 확인 절차를 거쳐 실행되어야 한다.

## 5. 제약 사항 (Constraints)

- **C-1**: Python 3.8 이상 환경에서 동작해야 한다.
- **C-2**: `requests`, `sseclient-py`, `python-dotenv` 패키지에 의존한다.
- **C-3**: Windows, macOS, Linux 운영체제를 모두 지원해야 한다.
