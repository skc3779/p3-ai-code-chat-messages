## 1. 지수 백오프란?

**지수 백오프(Exponential Backoff)**는 재시도 간격을 점점 늘려가는 방식입니다.

```
1차 실패 → 1초 대기 → 재시도
2차 실패 → 2초 대기 → 재시도
3차 실패 → 4초 대기 → 재시도 (최종 실패)
```

이 방식은 서버가 과부하 상태일 때 즉시 재요청하여 부하를 가중시키는 것을 방지합니다.

## 2. 동작 흐름

```
┌─────────────┐
│  API 호출   │
└──────┬──────┘
       ↓
┌──────────────────┐    성공     ┌──────────┐
│ HTTP 상태 확인   │───────────→│  완료    │
└──────┬───────────┘             └──────────┘
       │ 오류
       ↓
┌──────────────────┐    No      ┌──────────┐
│ 재시도 가능?     │───────────→│ 오류 반환│
│ (429/500/502/503)│            └──────────┘
└──────┬───────────┘
       │ Yes
       ↓
┌──────────────────┐    No      ┌──────────┐
│ 재시도 횟수 < 3? │───────────→│ 오류 반환│
└──────┬───────────┘            └──────────┘
       │ Yes
       ↓
┌──────────────────┐
│ 대기 후 재시도   │
│ (지수 백오프)    │ ──→ 맨 위로
└──────────────────┘
```

## 3. 대기 시간 계산

### 공식
```python
delay = BASE_DELAY × 2^attempt × jitter
```

### 예시 (BASE_DELAY = 1초)

| 시도 | 계산 | 지터(0.5~1.5) | 실제 대기 |
|------|------|---------------|----------|
| 0차 | 1 × 2⁰ = 1초 | × 0.8 | **0.8초** |
| 1차 | 1 × 2¹ = 2초 | × 1.2 | **2.4초** |
| 2차 | 1 × 2² = 4초 | × 0.9 | **3.6초** |

**지터(Jitter)**: 0.5 ~ 1.5 사이 랜덤값. 여러 클라이언트가 동시에 재시도하는 **Thundering Herd** 문제를 방지합니다.

## 4. 재시도 가능 오류

| HTTP 코드 | 설명 | 재시도 |
|-----------|------|--------|
| 200 | 성공 | - |
| 400 | 잘못된 요청 | ❌ |
| 401 | 인증 실패 | ❌ |
| 408 | 요청 타임아웃 | ✅ |
| 429 | Rate Limit | ✅ |
| 500 | 서버 오류 | ✅ |
| 502 | Bad Gateway | ✅ |
| 503 | 서비스 불가 | ✅ |
| 504 | Gateway Timeout | ✅ |

## 5. 사용자 알림

재시도 발생 시 콘솔에 메시지가 출력됩니다:

```
⚠️ API 오류 (429). 1.2초 후 재시도... (1/3)
⚠️ API 오류 (429). 2.8초 후 재시도... (2/3)
✅ 재시도 성공
```
